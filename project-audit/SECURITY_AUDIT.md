## 2. In-Depth Cryptography Audit

### 2.1 Encryption Algorithm
- **Algorithm:** **AES-256-GCM (Galois/Counter Mode)**
- **Key Length:** 256 bits (32 bytes).
- **IV / Nonce:** 96 bits (12 bytes), generated via `crypto.randomBytes(12)` uniquely for every single upload.
- **Authentication Tag:** 128 bits (16 bytes), generated by the GCM cipher.

### 2.2 Storage Envelope Specification
Files in `uploads/` follow the proprietary binary format:
```
+-------------------+--------------------+--------------------+-----------------------+
| Magic Header      | IV / Nonce         | Auth Tag (MAC)     | Ciphertext Payload    |
| 8 Bytes: CVLT_GCM | 12 Bytes (96 bits) | 16 Bytes (128 bits)| Variable Length       |
+-------------------+--------------------+--------------------+-----------------------+
```

### 2.3 Verification Evidence
In `tests/verifyCryptoSecurity.ts`:
1. When a single byte in ciphertext is flipped, the decipher throws: `Unsupported state or unable to authenticate data`.
2. When an unauthorized student requests download, authorization fails **before** the filesystem is touched or key is loaded into memory.
3. Plaintext files are never written to disk; file buffers are encrypted in memory prior to `fs.writeFile`.

## 3. Immediate Access Revocation: Attack Simulation

The standalone security engine was subjected to an adversarial attack simulation in `security-engine/tests/attack-simulation/attackSimulation.test.js`:

1. **Step 1:** Admin issues a confidential grant to Student A.
2. **Step 2:** Student A accesses the document ➔ Result: `ALLOW` (`ACCESS_GRANTED_BY_GRANT`).
3. **Step 3:** Admin immediately revokes Student A's access.
4. **Step 4:** Student A attempts to replay the same old document download link ➔ Result: `DENY` (`GRANT_REVOKED`).
5. **Step 5:** Student A attempts direct API invocation with cached credentials ➔ Result: `DENY` (`GRANT_REVOKED`).
6. **Step 6:** Audit log inspection confirms 1 ALLOW record and 2 DENY records with zero credential leakage.

## 4. Supabase Row Level Security (RLS) Verification

In `supabase/schema.sql`, PostgreSQL Row Level Security is explicitly activated across all six tables:
- `ALTER TABLE public.departments ENABLE ROW LEVEL SECURITY;`
- `ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;`
- `ALTER TABLE public.documents ENABLE ROW LEVEL SECURITY;`
- `ALTER TABLE public.access_grants ENABLE ROW LEVEL SECURITY;`
- `ALTER TABLE public.audit_logs ENABLE ROW LEVEL SECURITY;`
- `ALTER TABLE public.ai_access_requests ENABLE ROW LEVEL SECURITY;`

Security Definer Function `is_admin()` verifies that callers requesting privileged operations hold verified `admin` or `hod` roles in their authenticated profile before executing data queries.
